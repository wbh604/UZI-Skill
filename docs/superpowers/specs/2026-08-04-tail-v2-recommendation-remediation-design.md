# Tail v2 推荐治理与隔夜交易修复设计

日期：2026-08-04

## 结论

本修正案将尾盘决策系统从 `tail-v1` 升级为 `tail-v2`。系统继续生成 ETF 与隔夜个股候选，但只有唯一的生产决策链可以产生一个最终操作。任何 `no_trade`、`blocked` 或 `watch_only` 结果都不得被人工临时推荐覆盖。

系统立即启用严格的时效、追涨、冲高回落、相对强弱和次日失败退出门禁；同时在模拟盘中积累扣费后隔夜结果，再校准跨资产分数。在证据门未通过前，系统可以输出“最佳模拟操作”，但不得把它表述为已验证的实盘推荐。

## 根因与修复映射

### 1. 决策结果被人工绕过

2026-08-03 的正式任务输出 `no_uzi_approved_candidate`，但随后又出现未落盘的临时买单。修复后，只有同时满足以下条件的 `DecisionRun` 才是可操作结果：

- `status == recommended`；
- 恰好一个资金分配；
- 候选、分配和双源质量记录一致；
- `strategy_version == tail-v2`；
- 结果由 `final` 阶段落盘并可以通过 run ID 重放。

报告层对其余状态显示明确的 `DO_NOT_TRADE`。候选列表、聊天文本和预览阶段不是买单，不得拥有独立的买入价和仓位。

### 2. 过期价格和盘前逻辑混入尾盘决策

`final` 阶段必须重新读取数据，不得重用 `preview` 候选或盘前参考价。每个最终候选必须具备：

- 两个独立免费行情源，且质量判定为 `PASS`；
- 行情属于当前交易日，抓取延迟不超过现有配置上限；
- 14:10–14:30 当日尾盘快照序列；
- `max_buy_price` 基于 `final` 的 canonical quote，而不是旧日收盘价；
- 日线、交易状态和公告风险的最新可用交易日边界一致。

任一条件不满足时，该标的被拒绝；系统不得使用降级单源结果补齐买单。

### 3. 将当日尾盘强势直接外推为次日收益

`tail-v2` 保留尾盘动量，但不再让尾盘涨幅、VWAP 距离或日内位置单独推高候选。在进入评分前先执行以下硬门：

- 当日过度涨幅与高位收盘同时出现时，记为 `overextended_close`；
- 上午冲高后尾盘回落，且收盘区间位置低于门限时，记为 `intraday_reversal`；
- 个股未跑赢所属行业和宽基基准，记为 `relative_strength_below_gate`；
- ETF 跟踪市场已收盘、折溢价或代理价格异常时，记为 `underlying_dislocation`。

数值门限不根据一天的五只标的手工拟合。实施时先使用保守配置和边界测试，并将所有门限纳入配置哈希；后续只能根据版本化回测或前向模拟调整。

### 4. ETF 与个股分数缺乏净收益可比性

候选生成仍分为 ETF 和个股两条策略，但账户层不再盲目比较未校准的原始分数。每个候选增加可审计的证据：

- 扣除滑点、最低佣金和印花税后的预期净收益或保守代理分；
- 相似样本数和使用的样本时间边界；
- 基准相对收益；
- 证据等级 `unvalidated`、`shadow_calibrated` 或 `forward_validated`。

在历史类似样本或前向样本不足时，候选最多进入 `watch_only`。账户分配器只接受证据门达标且扣费后期望为正的候选。当前 60 交易日、40 笔模拟入场的正式放行门保持不变，不与 `tail-v1` 样本混合。

### 5. 次日退出规则不一致

ETF 和个股保留不同的费用和 T+1 约束，但使用同一退出状态机：

1. `exit_open` 记录次日开盘缺口和可交易性，不在 09:25 伪造成交。
2. `exit_check` 使用首个完整 5 分钟区间低点和当时 VWAP。
3. 高开后跌破首个 5 分钟低点或 VWAP 且无法快速收复时，记录 `failed_follow_through_exit`。
4. 硬止损、止盈和时间退出仍由版本化配置控制；动态失败退出不得扩大原硬止损。
5. 缺少完整 5 分钟快照或行情质量不是 `PASS` 时，退出阶段记录阻断，不伪造理论成交价。

## 系统边界

### 生产决策链

```text
归档与交易日历
        +
免费行情双源 -> 质量门 -> 当日尾盘特征
        +                              |
公告/交易状态 -> ETF/个股硬过滤 -> 证据分级
                                           |
                                扣费后统一择优
                                           |
                       recommended / watch_only / no_trade / blocked
                                           |
                          追加式模拟账本与次日退出
```

`workflow.py` 是状态权威，策略模块只能产生候选和拒绝原因，`portfolio.py` 只能从通过证据门的候选中选一个，`recorder.py` 不得推导新决策。

### 影子校准链

每个 `final` 阶段保留全部候选、拒绝原因和证据等级。模拟器对可成交候选记录次日开盘、首个 5 分钟、09:35、日内高低和时间退出结果。校准器按策略版本、资产类型、涨幅分组、区间位置和市场环境汇总净收益，但不自动修改生产阈值。阈值变更必须提升策略版本并重新开始前向计数。

## 状态与错误处理

- 双源缺失、日期越界、交易日历异常、公告风险未知或账本不一致：`blocked`。
- 数据可用但证据样本不足：`watch_only`，零分配。
- 数据和证据可用，但所有候选被策略门拒绝：`no_trade`。
- 恰好一个候选通过所有门并形成合法分配：`recommended`。
- 任何状态与分配矛盾都是不可恢复的本次运行错误，报告必须阻断并保留审计件。

## 测试设计

实施采用 TDD，至少覆盖：

1. `no_trade`、`blocked` 和 `watch_only` 都无法产生买单或可操作文案。
2. `preview` 候选无法在 `final` 阶段被重用，旧交易日价格必定被拒绝。
3. 两源时间、交易日、canonical quote 和买入限价在同一决策边界内。
4. 过度涨幅高位收盘、冲高回落、相对强度不足和 ETF 跟踪市场异常有稳定拒绝原因。
5. 证据不足的高分候选不能进入账户分配；证据达标且扣费后期望为正的候选才可统一择优。
6. 最终始终最多一个分配，不超过单标的和账户总暴露上限。
7. ETF 与个股都能在高开失败时触发首个 5 分钟低点/VWAP 退出，且不晚于硬止损。
8. 策略版本、配置哈希、输入时间、候选证据、拒绝原因和模拟成交均能从追加式记录重放。
9. `tail-v1` 与 `tail-v2` 前向样本不混合，旧样本不得使新版本提前达标。
10. 离线无 Token 端到端测试仍通过，不恢复付费源依赖。

## 非目标

- 不连接券商，不自动下单。
- 不保证每天推荐，不为了凑交易而降低门槛。
- 不用一天或五只标的结果训练参数。
- 不恢复全市场历史分钟线采集。
- 不删除或改写 `tail-v1` 已有决策和模拟记录。
- 不将 Tushare 周卡或 Token 变回日常决策的硬依赖。

## 验收标准

修复完成时必须有可重现证据证明：

- 2026-08-03 类型的“正式空仓后人工出买单”不再能通过报告契约。
- 过期盘前候选不能成为尾盘分配。
- 追涨、冲高回落和相对弱势标的会被明确拒绝或降为观察。
- 缺乏证据的候选零资金分配，有证据的候选才按扣费后净期望统一择优。
- 高开冲高失败的 ETF 和个股都有比固定宽止损更早的可审计退出。
- 完整相关测试、无 Token 端到端测试和实际本地阻断演练通过。
